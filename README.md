# Anagrams

A browser-based, two-player, real-time anagram race. Both players see the same six letters and have **60 seconds** to find as many words as they can. Highest score wins. Inspired by fast-paced anagram games.

## How to play

1. One player creates a room and shares the 6-character code (or the `?room=` link).
2. The other player joins. Both hit **Ready** → 3-2-1 → the round starts.
3. Spell words from the six letters — **type or click** the tiles. <kbd>Enter</kbd> (or the Submit button) submits, <kbd>Delete</kbd> removes a letter, <kbd>Esc</kbd> clears, <kbd>Space</kbd> (or Shuffle) reshuffles the tile display.
4. During the round you see your opponent's score and word count — never their words.
5. Results show both word lists side by side, plus the highest-scoring words nobody found.

### Scoring

| Word length | Points |
|---|---|
| 3 letters | 100 |
| 4 letters | 400 |
| 5 letters | 1,200 |
| 6 letters | 2,000 |

Minimum word length is 3. Wrong guesses cost nothing; a word can't be scored twice by the same player, but both players may score the same word.

## Development

Requires Node 20+.

```sh
npm install
npm run dev        # server on :3210, client on :5173 (proxies /ws)
npm test           # scoring, validation pipeline, puzzles, room state machine
npm run build      # client → client/dist, server → server/dist
npm start          # serve the built app on $PORT (default 3000)
```

A terminal client exists for playing without a UI:

```sh
npx tsx server/scripts/cli-client.ts create Ann
npx tsx server/scripts/cli-client.ts join <CODE> Bob
```

## Architecture

One Node process serves everything: Express serves the built React client and upgrades WebSocket connections on `/ws` on the same origin. The server is authoritative — it owns the letter set, the dictionary, the clock, and all scoring; the client only renders state and sends attempts. Rooms are in-memory objects (no database), garbage-collected 10 minutes after a round ends; a disconnected player has 15 seconds to reconnect with their score intact. Letter sets are generated by shuffling a common 6-letter seed word and are re-rolled until the puzzle has at least 2 vowels, 25 valid words, and 3 words of five-plus letters, so a 2,000-point solution always exists. The countdown is rendered locally against a server-time offset, and submissions are accepted up to 300 ms after the round ends to absorb network latency. A `shared/` module holds the protocol types and scoring table so client and server can't drift.

## Dictionary

Word list: [ENABLE](https://raw.githubusercontent.com/dolph/dictionary/master/enable1.txt) (Enhanced North American Benchmark Lexicon), public domain — filtered to 3–6 letter words (~29k) and committed at `server/data/words.txt`. Seed words come from intersecting ENABLE with common-word frequency lists ([google-10000-english](https://github.com/first20hours/google-10000-english), [FrequencyWords](https://github.com/hermitdave/FrequencyWords)). Regenerate with `npm run build:wordlist -w server`. The dictionary never ships to the client.

## Deployment

Deployed on [Render](https://render.com) via the committed `render.yaml` blueprint (build `npm install && npm run build`, start `npm start`, binds `$PORT`).

> **Note:** on Render's free tier the server spins down after ~15 minutes idle — the first load after that can take 30–60 seconds while it cold-starts. Live rooms don't survive a restart (in-memory by design); the app shows a clean "room expired" state.
